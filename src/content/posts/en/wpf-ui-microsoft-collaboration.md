In December 2023, I got an email I had to read twice. Microsoft's WPF team wanted to collaborate on bringing WPF UI functionality into the core .NET framework. I had started it as a personal project to make WPF applications look less like they were built in 2005. Somehow it had caught the attention of the people who build WPF.

## How This Started

I started WPF UI because I was frustrated with how hard it was to make WPF applications that looked at home on modern Windows. Everything looked dated. Even basic things like proper theming or modern controls needed hoops to jump through or fragile workarounds.

The idea was straightforward. I wanted controls that implemented the Windows 11 design language properly and handled theming automatically. Developers shouldn't have to become designers to make their applications look decent.

## The Numbers

WPF UI has grown beyond what I expected when I started it. It now has 8.8k stars on GitHub and 894 forks, and it's used in over 2,500 projects. 89 contributors have helped improve it.

The most visible use was Microsoft PowerToys, where WPF UI was the foundation when it adopted the new Fluent design. It also became a blueprint for Fluent UI in WPF, and my WPF UI Gallery app inspired Microsoft's WPF Gallery.

## What This Means

For developers, this collaboration means native modern controls in WPF without extra dependencies. It means smooth integration with existing projects, official Microsoft support for modern Windows design patterns, and continued innovation in desktop development.

For the wider community, it shows that open-source work can influence major frameworks and that community-driven development matters. It also shows that WPF still has a future.

## PowerToys Integration

Seeing WPF UI in Microsoft PowerToys Run was one of the most rewarding parts. PowerToys is one of the most popular developer tools on GitHub, and knowing my work helped millions of developers daily is still incredibly fulfilling.

## What's Next

Some functionality will become part of core WPF, but WPF UI will keep evolving. It will support older .NET versions, provide advanced custom controls, and offer experimental features. Community needs will keep driving it.

The collaboration with Microsoft doesn't change the open-source nature of WPF UI. If anything, it validates the approach and brings more resources to desktop application development.

## Personal Reflection

I couldn't have done this without the WPF UI community and contributors. Microsoft's WPF team saw the value of community-driven innovation. Developers trusted WPF UI in their projects, and many people sent feedback and bug reports.

What began as personal frustration with the state of WPF applications now influences the direction of the framework itself. It reminds me that individual contributions to open source can reach far beyond what you first imagine.

If you're building desktop applications and want them to look at home on modern Windows, you can find WPF UI on GitHub and read the documentation at wpfui.lepo.co. The project remains open to contributions and feedback.
